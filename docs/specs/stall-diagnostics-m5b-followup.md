# M5b, второй заход: две недоделки по повторному ревью

Тот же клон и та же ветка `fix/stall-review`. Правила, «Не трогать» и критерии AC-001…AC-005
из `docs/specs/stall-diagnostics-m5b.md` остаются в силе. Добавляется: этот файл тоже
закоммитить. `git push` запрещён.

## R1. D1 закрыт не полностью

`typeAndSubmit`, блок `if (!submitted)` после цикла подтверждения: `saveDebugSnapshot(...,
'submit_unconfirmed')` и `readUiErrorBanner` занимают время. Если 2xx на POST приходит в
это окно, `postAccepted` больше не проверяется, бросается `page_load_failed`, и
`completeText` повторяет уже принятую отправку. Ревьюер это воспроизвёл.

Исправление: после диагностики, прямо перед `throw`, ещё раз вызвать
`throwBackendPostFailure(capture, onSubmitted)` и проверить `capture?.postAccepted`. Если
POST принят, ошибку не бросать: идти по пути подтверждённой отправки. Тест в
`scripts/test-stall-review.js`: POST 2xx, пришедший во время снапшота `submit_unconfirmed`,
даёт ровно одну отправку.

## R2. D4 закрыт не полностью

`raceDeadline(p.screenshot({ path }))` не отменяет сам скриншот: PNG может записаться уже
после освобождения очереди и ротации. При `STALL_SNAPSHOT_KEEP=1` остаётся лишний PNG, а
следующее неудачное сохранение может удалить новую полную пару.

Исправление: снимать скриншот в буфер (`p.screenshot({ fullPage: true })` без `path`) и
писать `.png` самим, только если буфер пришёл до дедлайна. Поздний результат не пишется
никуда. Тест: скриншот, который резолвится после дедлайна, не создаёт файл и не ломает
ротацию при `STALL_SNAPSHOT_KEEP=1`.
